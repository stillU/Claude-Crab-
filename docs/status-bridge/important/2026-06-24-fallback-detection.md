# 进程检测兜底

当信号通道不可用时（hook 未触发、状态文件长时间未更新），status-bridge 通过检测 claude 进程作为兜底判断。

## 检测策略

### 进程存在性检查（每 3 秒）

- 检查进程列表是否存在 `claude` 相关进程
- 进程不存在 → 发送 IDLE 信号

### CPU 活跃度判断（进程存在时）

- 采样 claude 进程的 CPU 使用率
- CPU > 阈值（如 5%）→ 推断 WORKING
- CPU ≤ 阈值 → 推断 IDLE

## 优先级

信号文件更新 > 进程检测推断

- 信号文件在 10 秒内有更新 → 以信号文件为准，忽略进程检测
- 信号文件超过 10 秒未更新 → 启用进程检测兜底
- 进程检测结果与信号文件一致 → 无变化
- 进程检测结果与信号文件不一致 → 以信号文件为准（进程检测仅在没有信号时生效）

## 兜底触发条件

仅在以下情况启用进程检测：
1. 信号文件超过 10 秒未更新
2. 信号文件目录不存在或不可读
3. 程序启动 5 秒后仍未收到任何信号

## 实现要点

- 使用 Rust `sysinfo` crate 获取进程列表和 CPU 使用率
- 轮询间隔 3 秒，避免频繁采样消耗资源
- 不向信号文件写入进程检测结果（只读，不修改状态文件）
